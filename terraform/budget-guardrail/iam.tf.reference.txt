# terraform/budget-guardrail/iam.tf.reference
#
# NOT ACTIVE TERRAFORM CONFIG. Renamed .reference so this directory's
# `terraform plan`/`apply` never parses or manages it.
#
# This is a documented record of budget-admin's own permissions policy,
# created manually via the AWS console under root -- same precedent as
# MyLabBudgetCapsAt5, which is also unmanaged by Terraform.
#
# WHY THIS IS UNMANAGED, NOT JUST UNAPPLIED:
# IamPolicyForBudgetAction's Resource pattern below is "*budget*" (lowercase),
# which does NOT match this policy's own name, "BudgetGuardrailAdmin"
# (capital B) -- IAM resource-ARN matching is a literal, case-sensitive
# string match, no case-folding. Attempting to `terraform import` this
# policy under budget-admin's own credentials fails with AccessDenied,
# because budget-admin cannot read/version a policy whose ARN doesn't
# match its own grant.
#
# This is being kept, not "fixed" by widening the pattern. Bringing this
# policy under budget-admin's own managed state would mean budget-admin
# can read and create new versions of its own attached policy -- a step
# toward self-modification that the original identity split (see NOTES.md,
# 8/14/26) was built specifically to prevent. The case mismatch was
# accidental, but it happens to enforce the correct boundary: root manages
# budget-admin's own rights; budget-admin manages the guardrail pointed at
# terraform-lab. Different identities, different scopes, by design.
#
# If budget-admin's own permissions ever need to change, do it via root,
# console or a separate root-owned Terraform state -- never from this
# directory's budget-admin-scoped provider.
